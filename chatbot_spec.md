# Job Search Intelligence Chatbot

## Overview

The chatbot should not be a generic "AI career chatbot." It should be a **Job Search Intelligence Chatbot** whose primary source of truth is the user's application database.

The overall architecture:

```text
                    JOB SEARCH CHATBOT
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
       DATABASE         ANALYTICS          AI
          │                │                │
     exact facts       calculations     interpretation
          │                │                │
          └────────────────┼────────────────┘
                           ▼
                    Natural-language answer
```

The key principle is:

- **Database / SQL** → factual questions
- **Analytics engine** → calculations and metrics
- **LLM / AI** → interpretation, pattern detection, recommendations, and natural-language responses

---

# 1. Current Application Status

The chatbot should answer questions such as:

- How many jobs have I applied to?
- How many applications are still active?
- How many companies rejected me?
- How many offers do I have?
- What applications are currently in the interview stage?
- Show me all applications waiting for a response.
- Which applications changed status this week?

Example:

```text
User:
"How many active applications do I have?"

        ↓

LLM identifies intent

        ↓

SQL query

        ↓

Database returns 27

        ↓

Chatbot:
"You currently have 27 active applications."
```

The number should come from the database rather than being generated by the LLM.

---

# 2. Application Funnel Questions

The chatbot should understand the entire application funnel:

```text
Applications
     ↓
OA
     ↓
OA Passed
     ↓
Interview
     ↓
Final Round
     ↓
Offer
```

Users can ask:

- What's my application-to-interview conversion rate?
- What's my OA pass rate?
- How many applications reached the interview stage?
- How many interviews converted to final rounds?
- How many offers have I received?
- Where am I losing the most applications?

Example:

```text
120 Applications
       ↓
32 OAs
       ↓
21 OA Passes
       ↓
12 Interviews
       ↓
4 Final Rounds
       ↓
1 Offer
```

The chatbot could respond:

> You have submitted 120 applications. 32 resulted in an OA, and 21 of those were passed. 12 progressed to interviews, 4 reached final rounds, and 1 resulted in an offer.
>
> Your biggest funnel drop-off is Application → OA, at 26.7%.

# 3. Rejection Analytics

Users can ask:

- Why am I getting rejected so often?
- What's my rejection rate?
- At which stage do most rejections happen?
- Which types of jobs reject me most frequently?
- Has my rejection rate improved over time?

The AI should combine:

```text
Application outcomes
+
Job descriptions
+
Roles
+
Skills
+
Resume version
+
Application source
+
OA performance
+
Interview outcomes
```

Example:

> Based on your 84 applications, your largest bottleneck appears to be getting from application → OA/interview.
>
> Your OA pass rate is relatively strong, so once you reach an assessment, you tend to progress.
>
> Your interview conversion is also better for ML/AI roles than general SWE roles.
>
> Possible interpretation: your current profile may be better aligned with specialized ML/AI positions than broad SWE postings.

Important: the AI should distinguish **observed facts** from **hypotheses**. It should not claim that a small dataset proves why a user was rejected.

# 8. Resume Intelligence

If the system stores the resume version used for each application, the chatbot can compare performance.

Example:

```text
Resume v1
Resume v2
Resume v3 — ML focused
Resume v4 — SWE focused
```

Users can ask:

- Which resume is performing best?
- Did my new resume improve my interview rate?
- Which resume did I use for successful applications?
- Compare Resume v3 and v4.

Example:

```text
Resume v3
40 applications
4 interviews → 10%

Resume v4
30 applications
7 interviews → 23.3%
```

The chatbot should explain:

> Resume v4 has a higher observed interview rate, 23.3% vs 10%. However, the roles and application sources also changed, so this isn't enough to establish that the resume alone caused the improvement.

This is an excellent example of evidence-based AI rather than generic AI advice.

  "oa_pass_rate": 0.72,
  "offer_rate": 0.008,

> 2. Targeting ML/AI roles where your interview rate is higher.
> 3. Improving the application → OA conversion funnel.
> 4. Following up on applications that haven't changed status for several weeks.

# 13. Natural-Language Database Queries

This can be one of the coolest features.

Instead of forcing users to use many filters:

```text
Company: [ ]
Role: [ ]
Status: [ ]
Platform: [ ]
Date: [ ]
```

they can ask:

> Show me all active ML jobs I applied to in the last month through LinkedIn.

The LLM identifies the filters:

```text
role = ML
status = active
date > 30 days ago
source = LinkedIn
```

Then the backend executes a validated query against PostgreSQL.

The flow:

```text
User question
     ↓
LLM determines intent
     ↓
Backend creates/validates query
     ↓
PostgreSQL
     ↓
Structured results
     ↓
LLM explains results
```

Examples:

- How many applications do I have?
- Show my active applications.
- Which companies rejected me?
- What's my OA pass rate?
- What changed this week?

**Database / SQL driven.**

---

## 🔵 Mode 2 — Analyze My Data

Examples:

- Why is my conversion rate low?
- What are my strongest roles?
- Which application channel works best?
- Where is my funnel bottleneck?

**Analytics + AI driven.**

---

## 🟣 Mode 3 — Help Me Decide

Examples:

- Should I focus on ML or SWE applications?
- What should I improve?
- Where should I spend my application time?
- What patterns do you see in my applications?

**AI reasoning over historical data.**

# 17. Recommended Architecture

```text
                     USER
                      │
                      ▼
                 CHATBOT UI
                      │
                      ▼
                 LLM / Agent
                      │
              Intent Detection
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
    SQL Query      Analytics      AI Analysis
        │             │             │
        ▼             ▼             ▼
    PostgreSQL    Python/SQL      LLM Context
        │             │             │
        └─────────────┼─────────────┘
                      ▼
                 Final Answer
```

Important:

> Do not let the LLM directly "guess" the database.

Use:

```text
User question
     ↓
LLM determines what data is needed
     ↓
Backend validates/executes query
     ↓
Structured result
     ↓
LLM explains result
```

This gives you a much more reliable architecture.

# Core Design Principle

The strongest architectural statement for the project is:

> **The LLM does not invent the analytics. The analytics engine calculates the metrics from PostgreSQL, and the LLM interprets those structured results.**

That makes the AI component technically mature and gives you a clear separation between:

```text
Deterministic Layer
    ↓
Applications
Statuses
Timestamps
Conversion rates
Rejection rates
OA pass rates
Interview rates
Company statistics
Source statistics
    ↓
AI Intelligence Layer
    ↓
Pattern identification
Explanations
Recommendations
Summarization
Natural-language questions
```

The final product can therefore be positioned as:

> **An AI-powered Job Search Intelligence Assistant that combines automated application tracking, career-portal monitoring, analytics, and conversational querying over a user's historical job-search data.**
